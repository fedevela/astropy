# WCS-003 Architecture Artifact

GUID: `WCS-003`

## Requirement-to-Architecture Map

- `WCS-003` (empty list/array inputs keep output-container and dtype/shape conventions)
  - Obligation 1 (`WCS-003.1`): `wcs_pix2world([], [], 0)` returns list-based, per-axis zero-length outputs.
    - Structural pressure: preserve input container semantics at the conversion boundary.
    - Home: `astropy/wcs/wcs.py` → `WCS._array_converter` → tuple-call branch (`len(args) == self.naxis + 1`) → `_return_list_of_arrays`.
  - Obligation 2 (`WCS-003.2`): `wcs_pix2world(np.array([]), np.array([]), 0)` returns array-convention outputs, each axis `(0,)` and float dtype.
    - Structural pressure: preserve ndarray output convention and numeric dtype selection for empty-valid payloads.
    - Home: same branch in `WCS._array_converter` (`_return_list_of_arrays`).
  - Obligation 3 (`WCS-003.3`): list-based and ndarray-based empty outputs match existing conventions used for equivalent non-empty inputs, without synthetic expansion or shape inversion.
    - Structural pressure: enforce one structural conversion path with deterministic container selection and no synthetic row generation.
    - Home: tuple-form dispatcher contract in `WCS._array_converter`, plus existing empty short-circuit path in `_return_list_of_arrays`.

## Placement Decisions

- Owner: `WCS._array_converter` in `astropy/wcs/wcs.py` owns empty-input detection and output materialization for axis-tuple calls.
- Adjacent seam: `WCS.wcs_pix2world` remains the public API surface and delegates unconditionally to `_array_converter`.
- Storage of container convention marker:
  - A local pre-coercion marker set near the `len(args) == self.naxis + 1` branch (e.g., list-convention vs ndarray-convention) is required so output type/shape can be deterministically reconstructed in `_return_list_of_arrays`.
- Traceability seam:
  - `astropy/wcs/tests/test_wcs_issue_30_wcs_003_traceability.py` carries obligation names and call patterns for this issue.

## Boundaries

- Outside boundary:
  - Input validation by public API shape and arity.
  - Test-facing verification lives in `astropy/wcs/tests/`.
- Inside boundary:
  - Tuple-form axis normalization (`_array_converter`).
  - Empty-input gate (`all(axis.size == 0 for axis in axes)`), currently in `_return_list_of_arrays`.
  - Container-convention selection and empty-output materialization.
- Boundary rule:
  - On empty payloads, `_array_converter` must not invoke `func`, `_denormalize_sky`, or `_normalize_sky`.

## Contracts

- Empty-input contract:
  - Trigger: `sky == 'output'` and axis path enters `_return_list_of_arrays` with all axis payloads empty.
  - Axis count: fixed to `self.naxis` for tuple-form calls.
  - Shape contract: per-axis output shape equals broadcastable axis shape; for 1-D empties this is `(0,)`.
  - Container contract:
    - If original args are Python list axes, return list-style outputs.
    - If original args are ndarray axes, return array-style outputs.
  - Dtype contract: outputs use floating-point dtype to match non-empty array-convention behavior.
- Determinism contract:
  - Empty-output choice is independent of `origin` when output cardinality is already fixed by tuple arity and emptiness.

## Dependency Direction

- `all_pix2world` and `wcs_pix2world` → `_array_converter`.
- `_array_converter` →
  - `np.broadcast_arrays` for non-empty compatibility checks,
  - `WCS._all_pix2world`/`func` only via non-empty return path,
  - `_denormalize_sky`/`_normalize_sky` only in non-empty branches.
- Empty-input contract is terminal; it short-circuits and isolates wcslib/sky-normalization dependencies.

## Integration-Seam Skeletons

- `astropy/wcs/wcs.py`:
  - `_array_converter` tuple-form branch should maintain an explicit `input_container_mode` value derived from `args[:-1]` before coercion.
  - `_return_list_of_arrays` should branch terminal empty-output materialization by `input_container_mode` and preserve the broadcast-derived shape contract.
- `astropy/wcs/architecture/wcs_003.md`:
  - This seam records and enforces where implementation must attach container-preservation logic.
